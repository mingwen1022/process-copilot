toB · AI 流程设计 Agent

不是又一个 OA 平台，
而是一条会自我优化的流程闭环。

从原始素材直接合成标准流程，推送上线流转，再用运行数据反查提效点与堵点， 最终把洞察反哺回设计端 —— 让「设计」和「运行」互为燃料。

设计 → 上线流转 → 运行数据分析 → 优化反哺设计 ↺

纯前端匹配，不联网、不存储。仅作为四模块职责的一个直观导览。

四个模块 · 点开看职责

M1 护城河 ①

设计 Agent + 规则 RAG + 评测

从 raw_sources 抽取标准流程 JSON，配套评测驱动调优。

LangGraph 编排：抽取 → Pydantic 校验对比 → 首次不过回跳复查一次 → 生成 Excel / draw.io 产物。 评测驱动 prompt 迭代，先把单锚案例做深做透，再横向铺 RAG 与对话式修改。
M2 冻结 · 薄做

薄运行时（数据底座）

只作为运行数据的产生与承载层，刻意冻结、停止扩展。

重运行时（服务层 + SPA）已标注冻结，不再往 OA 平台化方向加功能；引擎本身保留、薄做。 它的价值不在功能多，而在于稳定地喂出真实运行数据给 M3。
M3 护城河 ②

运营分析 Agent

吃运行数据，产出提效点、堵点与优化建议。

面向真实流转日志做提效 / 堵点分析，把「哪里慢、哪里绕、哪里返工」变成结构化洞察 —— 这是让产品从「能画流程」升级到「能改进流程」的关键一跃。
M4 闭环

闭环反哺

把 M3 的洞察回灌 M1，形成设计↔运行的正循环。

分析结论不是终点，而是下一轮设计的输入：调整规则、补齐缺失、修正流程结构。 闭环一旦转起来，每一次上线都在让下一版设计更准。

M1 工作流 · LangGraph 节点

load_case_context → process_extraction_agent → validate_and_compare → artifact_generation_agent → write_run_outputs

只有抽取与产物生成两个 agent 节点，其余为确定性节点。校验不过时回跳复查一次； Excel 与 draw.io 由 LLM 依 skill 指令现场生成并校验，非固定模板。

设计取舍

  • 先做深单案例，再横向铺量
  • 评测驱动，而非拍脑袋调 prompt
  • 运行时刻意薄，把重心留给两条护城河
  • 产物由 LLM 现场生成，避免模板僵化
  • V1 不引入 MCP，保持链路可控
  • 闭环优先于功能广度
