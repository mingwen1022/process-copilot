流程设计 Agent V1 - Repo Overview

当前仓库用于把多份模拟 raw source 文本整合为企业 OA 流程标准定义， 再生成 JSON、可读 Excel、draw.io 流程图和缺失/差异报告。

1. 项目定位

Input 原始输入

每个流程 case 下有 5 份 raw_sources/*.txt，模拟需求文档、邮件、群聊、会议纪要等零散来源。

Core 标准化输出

核心输出是符合 Pydantic ProcessDefinition 的 process_def.json。

Artifacts 可读产物

Artifact agent 调用 Excel skill 和 draw.io tool，生成 process_readable.xlsx 与 process_flow.drawio。

重要边界：data/*/standard/*.json 只用于最终 eval 对比，不参与 runtime prompt、validation 或 routing。

3. 当前 LangGraph 工作流

节点 类型 核心职责 主要输出
load_case_context function node 读取 case 目录，拼接 raw_sources 为上下文。 raw_sources, source_context, case_id
process_extraction_agent agent node 调用 Bedrock Claude，用 structured output 抽取 ProcessDefinition；解析失败时做一次格式 repair。 candidate_process, llm_raw_output, messages*.json
structural_validator function node Pydantic 兜底校验、提交路径 target 引用、字段/附件环节引用合法性。 schema_validation_report.json, routing state
business_validation_agent agent node + deterministic routing wrapper 看 raw sources 与候选 JSON，判断大块缺失、明显遗漏、无依据编造；用 found_in_raw 决定是否回抽取。 business_validation_report.json, validation_feedback
artifact_generation_agent agent node with tools 调用 Excel skill tool 和 draw.io XML tool，生成可读产物。 process_readable.xlsx, process_flow.drawio, artifact report
write_run_outputs function node 写最终 JSON、runtime reports、eval reports 和 output manifest。 process_def.json, comparison_report.json, missing_report.md, output_manifest.json

4. 核心功能清单

抽取与校验

  • 从本地 .txt raw sources 合成标准 ProcessDefinition。
  • 使用 ChatBedrockConverse.with_structured_output 做 schema 约束。
  • 结构错误或引用错误可回到 extraction agent 复查一次。
  • 业务校验 agent 不看 standard，只基于 raw sources 举证。
  • 业务 blocking 且 found_in_raw 时回 extraction；not_found_in_raw 时输出缺失报告。

产物生成

  • Excel 由 artifact agent 读取外部 xlsx/SKILL.md，让 LLM 动态生成 Python 脚本。
  • Excel 生成后会检查 workbook 内容、错误单元格、术语和环节展示方式。
  • draw.io 由 LLM 直接生成 XML，并校验 mxfile / diagram / mxGraphModel。
  • draw.io 生成要求字体颜色为黑色，便于在深色/浅色背景中阅读。
  • 每次 run 按节点目录保存 raw output、messages、校验报告和产物。

5. 标准 Schema 范围

V1 标准模型定义在 data/schema/process_schema.py。顶层对象是 ProcessDefinition：

模块 说明
meta 流程编号、流程名称、版本、责任部门、描述、适用范围、入口。
form_fields 字段序号、字段名、必填/可见/可编辑环节、组件类型、逻辑说明、默认值、选项、长度等。
flow_nodes 审批环节、处理人配置、意见配置、限时、提交路径和路径条件。
attachments 附件类型、上传环节、必传环节。
roles 流程角色/业务角色、挂接人员、所属部门。

7. 运行与配置

运行单个 case

uv run python -m app.workflows.process_v1 --case data/01_leave_request --out runs/01_leave_request --verbose

默认会给 --out 目录追加时间戳；如需固定输出目录，可加 --no-timestamp。

校验数据集

uv run python scripts/validate_dataset.py

运行测试

uv run pytest

Bedrock 环境变量

变量 用途
BEDROCK_MODEL_ID Claude Sonnet 模型 ID，传入 ChatBedrockConverse(model=...)。
AWS_REGION / AWS_DEFAULT_REGION Bedrock region。
AWS_BEARER_TOKEN_BEDROCK 单个 Bedrock API key，不使用 AWS access key / secret key。
BEDROCK_MAX_TOKENS, BEDROCK_TEMPERATURE 可选模型生成参数。

10. 当前设计约束

  • V1 不引入 MCP runtime；本地 xlsx skill 是 prompt/指令资产，由 artifact agent 的 tool 内部读取。
  • Excel 和 draw.io 不是 graph 节点，而是 artifact_generation_agent 的 tools。
  • 业务 validator 只看 raw 和候选输出，不看 standard。
  • LLM 不直接控制 graph next node；条件路由由确定性 Python 函数根据结构化结果计算。
  • 如果 raw 本身缺信息，系统不编造，输出缺失报告供人工补 raw data。
