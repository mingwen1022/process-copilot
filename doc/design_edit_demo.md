# 对话式修改 Demo（M1 交互层）

> 真实 Bedrock 端到端跑出的一段对话式修改，用于验证 harness："LLM 只解析意图、
> 产出 typed 编辑操作；应用/校验/diff 全部确定性代码"。案例：员工请假申请流程。

## 场景

已有一份请假流程草稿：起草 → 部门主管审批（同意则结束，不同意退回起草）。
用户想追加一条业务规则：**请假超过 10 天时，部门主管同意后还要再送总经理审批**。

## 用户指令

> 请假天数超过10天时，部门主管审批同意后需要再送总经理审批一次；总经理同意后流程结束

## AI 回复

> 已完成以下修改：
>
> 1. 「部门主管审批」环节新增一条路径「送总经理审批」，条件为「结论性意见=同意 且 请假天数>10」，目标指向新增的「总经理审批」环节；原「流程结束」路径条件调整为「结论性意见=同意 且 请假天数≤10」。
> 2. 新增「总经理审批」环节，处理人为本公司总经理（单人处理），需填写结论性意见；同意则流程结束，不同意则退回起草。

## 解析出的结构化编辑操作（typed，非自由文本）

| op | 说明 |
|---|---|
| `update_submit_path` | 更新"部门主管审批"路径"流程结束"的 condition |
| `add_submit_path` | 为"部门主管审批"新增路径"送总经理审批" |
| `add_flow_node` | 新增环节"总经理审批" |

三个 typed 操作由一条中文指令一次性解析产出，`apply_edit_operations` 确定性应用、零报错。

## Diff（结构化，UI 渲染为 diff 卡片）

```
新增环节"总经理审批"
环节"部门主管审批"新增路径"送总经理审批"
环节"部门主管审批"路径"流程结束" condition：结论性意见=同意 → 结论性意见=同意 且 请假天数≤10
```

## 校验结果

编辑后自动跑结构+业务校验：`status=WARN`，3 个 warning（均为"未配置处理期限"，不阻断），无 blocking 项——新增节点/路径自洽（无悬空引用、无缺失处理人）。

## 这段 demo 说明什么

- **通用在交互，专用在工具**：一句自然语言指令，agent 只做"理解要做什么"，具体怎么改（新增节点+改路径+加路径）由确定性的 `apply_edit_operations` 执行，不经过第二次 LLM 判断。
- **diff 即确认依据**：改动是否合理，靠结构化 diff 卡片直接看，而不是要求用户读一遍 JSON。
- **范围守卫 + 反问**（另两个已验证场景，未收录完整 transcript）：要求"发布上线+重置密码"这类超范围指令会被拒绝并说明原因；"再改一下"这类模糊指令会被反问而不是瞎改。
- **单步 undo**：应用后如果发现不对，可一键撤销回到编辑前的草稿（见 `doc/产品功能全景.md` 模块 4）。
